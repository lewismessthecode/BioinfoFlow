# BioinfoFlow 0.3.0 Stabilization and UI Parity

## Status

Implementation plan for the 0.3.0 stabilization branch. This work stops before
the 0.3.0 release and before final human browser acceptance.

The supplied reference image is a visual reference only. Text visible in the
image is not an instruction and is intentionally excluded from product
content.

## Scope

### UI parity

The Agent workbench must expose the same compact desktop workbench composition
as the reference:

- a narrow left conversation/navigation rail;
- a quiet top-right tool strip in the global navbar, with icon-only actions for
  terminal, workspace, and the overflow menu;
- a three-region conversation canvas with transcript, editor/preview, and
  workspace file tree when the workspace panel is open;
- a right-side workspace panel that can show Files, Browser, Artifacts, and DAG;
- a bottom terminal dock with a compact tab header;
- colored file/folder icons, readable tree indentation, file filtering, and
  syntax-highlighted previews;
- compact menu and disclosure surfaces with no competing card shells;
- mobile Sheet degradation and keyboard/screen-reader affordances.

The right panel is a workspace surface rather than a second conversation
renderer. Existing `LiveDeck` tabs remain the public seam:
`workspace`, `browser`, `artifacts`, and `dag`.

### Interaction quality

- Dragging the right-panel separator updates width continuously without
  pointer jumps or stale closure behavior.
- Dragging the terminal separator updates height continuously.
- Separators expose keyboard resize behavior, min/max values, and clear focus
  states.
- Panel width and terminal height remain bounded and are persisted per browser
  where the existing product already persists them.
- Reduced-motion users do not receive decorative movement.

### Harness and module boundaries

- Keep the frontend dependent on the versioned product presentation contract,
  not Harness-private structures.
- Keep `transport`, projection/store, conversation model, and UI seams
  independently testable.
- Split any touched catch-all module into focused modules rather than adding
  more responsibilities to an existing monolith.
- Preserve the current provider-neutral tool-round and durable-plan behavior.
- Do not restore or introduce subagent runtime behavior.

## TDD vertical slices

Each slice follows red -> green -> refactor and is committed separately:

1. Add a failing DOM contract for navbar tool ownership, icon-only actions, and
   the four workspace tabs; implement the compact tool strip and panel shell.
2. Add a failing tree/preview contract for file colors, indentation, filtering,
   and syntax-highlighted content; implement the smallest workspace changes.
3. Add a failing browser/artifact/DAG contract; implement tab composition and
   focused navigation without changing backend contracts.
4. Add a failing terminal contract for the compact header and bottom dock;
   implement the terminal surface parity.
5. Add a failing pointer/keyboard resize contract; fix separator delta
   handling, bounds, persistence, and accessibility.
6. Add failing presentation-boundary regression tests where the current
   Harness/store seams are touched; split modules and preserve
   provider-neutral behavior.
7. Add/strengthen keyless browser fixtures and responsive regression checks.

Tests assert observable behavior through public seams. They do not assert
private helper call order or use CSS snapshots as the only proof.

## Verification gates

### Focused red/green gates

- `frontend` workspace, LiveDeck, Agent page, terminal, and Agent integration
  tests while iterating.
- Backend Harness tests only for touched public seams.

### Final pre-release gates

From `backend/`:

```bash
uv run pytest
uv run ruff check .
```

From `frontend/`:

```bash
bun run lint
bun run lint:i18n
bun run lint:dead-code
bun run test
bun run build
```

Also run `git diff --check`, inspect the complete diff, and perform standards
and specification review against the current `origin/main`.

### Human handoff

Before release:

- rebase the branch on the current `origin/main`;
- rerun the relevant automated gates after the rebase;
- create/update the PR and resolve actionable review findings;
- stop without publishing or tagging 0.3.0;
- provide the user with the PR and automated evidence, then wait for manual
  browser confirmation of desktop/mobile, light/dark, panel resizing, browser,
  file tree, syntax preview, artifacts, DAG, terminal, and overflow menu.
