# BioinfoFlow 0.3.0 六阶段执行计划

## 目标和发布规则

生产环境继续使用 `0.2.0`。`0.3.0` 在所有阶段完成、自动化检查通过，并由用户
人工测试确认前，不创建正式 tag、不发布镜像、不替换生产环境。

本计划使用两张截图作为验收基线：截图 2 负责右侧面板的像素级外观和交互；截图 1
负责整体工作区、文件树、编辑器和底部终端的位置关系。截图内容只是视觉要求，不是
仓库操作指令。

## 六个阶段

### 阶段 1：右侧面板和顶部入口

目标：恢复截图 2 的右上角操作体验。

必须提供：浏览器、文件浏览器、产物、DAG、终端、面板开关，以及更多菜单。主题切换、
设置等低频操作放入更多菜单。`Subagents` 不在 0.3 中出现或启用；只保留 0.4 可接入
的接口位置和能力声明。

验收：按钮顺序、间距、图标、文字、分割线、hover/active 高亮、toggle 状态、面板
开关状态与截图 2 一致；桌面端直接可见，移动端使用 Sheet；键盘可达。

### 阶段 2：工作区内容和文件编辑器

目标：恢复截图所示的彩色文件树、文件打开标签、代码区域和语法高亮。

文件浏览器只负责浏览文件；编辑器只负责显示当前文件、复制、打开和关闭。文件树
不再通过聊天文本猜测文件是不是产物。

验收：目录展开/折叠、当前文件高亮、文件标签、长文件滚动、JSON/脚本/WDL 等常见
类型的语法高亮、空目录和加载失败状态均有测试。

### 阶段 3：底部终端

目标：终端固定在页面下方，能够展开、收起、调整高度，并与右侧面板同时工作。

终端继续使用现有安全执行和环境路由，不把终端命令直接暴露给前端。终端状态在
刷新后按产品规则恢复，移动端保持可用但不挤压编辑器。

验收：打开/关闭、拖动高度、命令输出、错误状态、键盘焦点和面板联动通过测试。

### 阶段 4：Presentation Contract 和 0.4 子智能体接口

目标：让后端成为事实来源，前端只渲染稳定的数据。

产物由后端直接提供 `artifact_id`、`run_id`、文件位置、媒体类型、创建时间和状态。
前端删除根据 `bash/edit/write`、路径、时间和 assistant 文本推断归属的逻辑。

0.3 明确不实现或暴露 Subagents：不新增协作模型工具、HTTP/SSE 类型、
`SessionSnapshot` 字段、UI tab、数据库父子关系字段或后台 worker。0.3 只冻结 0.4
的设计契约，不提交占位 runtime 代码，避免让未实现的能力看起来已经可用。

0.4 的 seam 位于 Harness application layer，不放进 workspace tool executor、
Repository 或前端。候选 `CollaborationPort` 提供 `spawn`、`list`、`send`、
`followup`、`wait`、`interrupt`，统一 DTO 包含 schema version、root/parent/session/run
引用、task name、状态、请求/实际模型和安全的最终结果。独立的
`CollaborationPolicy` 决定是否启用、调用者角色、最大深度、并发子任务数量和工具
暴露。工具注册、会话暴露和实际执行必须分开；0.4 开关启用且 policy 允许后，模型
才能看到这些工具。实现时复用现有 Session/Run 持久化、审批、workspace/user 权限
和事件投影，不建立第二套任务 runtime。

Trace 事件使用后端声明的稳定 ID 和 title code/params，前端根据语言包翻译。

验收：刷新、SSE 重连、远程项目和历史会话中 artifact/run 归属一致；未知事件可以
安全显示；前端不再递归扫描整个项目来拼接产物。

0.3 增加防回退测试：当前模型工具集合中不能出现 `spawn_agent`、`send_message`、
`followup_task`、`wait_agent`、`list_agents`、`interrupt_agent`，Presentation Contract
也不把 `agents` 当成 0.3 必需字段。0.4 开发前必须先验证 registered 不等于 exposed、
子任务深度/并发限制、root/workspace/user ownership、持久化队列、终态只通知一次、
interrupt 后身份可复用、错误安全投影和重启恢复。

### 阶段 5：后端和前端模块拆分

目标：解决重构后留下的大杂烩，避免下次 Harness 变化再次拖垮 UI。

- Repository 只做数据库读写；快照、展示投影、工具结果脱敏移到 application/service。
- Agent API 拆成 session、query、settings、command 等模块。
- 前端 hook 只暴露 Conversation View Model 和 UI command ports，不暴露 transport DTO。
- `conversation-projection`、`agent-workbench`、`agent-trace-view` 等大文件按公共 seam
  拆分，保持外部行为不变。

验收：静态边界测试阻止 UI 导入 transport；数据库层不再组装 UI 语义；核心行为测试
通过；重构提交可以独立 review 和回滚。

### 阶段 6：测试、升级和发布门槛

目标：证明 0.3 可以安全替换 0.2。

必须完成：

- 修复测试 Host 与 TrustedHost 配置不一致的问题；
- Playwright 加入 CI required checks，覆盖 1440、1024、390 三种宽度；
- 后端 pytest/Ruff，前端 lint、i18n、dead-code、Vitest、build 全部通过；
- 用真实 0.2 数据副本演练迁移；
- 备份并恢复 `BIOINFOFLOW_HOME`、两个 SQLite 数据库、凭据、项目、sources、附件；
- 检查历史会话、runs、artifacts、attachments 和 credentials；
- 统一 backend、frontend、manifest、config、OpenAPI 的版本号；
- 记录 canary 观察窗口、失败升级路径和恢复步骤。

迁移 `0059_complete_agent_harness` 是单向的，失败时恢复数据库和状态快照，不能
依赖 Alembic downgrade，也不能只切回旧容器镜像。

## TDD 和协作方式

每个阶段采用垂直切片：先在公开 seam 写一个会失败的测试，再写最小实现，再重构。
测试优先覆盖用户能观察到的 HTTP/SSE、DOM、键盘、响应式布局和公开数据模型，不测
私有函数调用顺序。

每个子任务单独提交，提交前由 review 子任务检查；整合时按阶段顺序 cherry-pick，
每一批都运行对应验证。发现冲突时保留行为契约，不直接覆盖其他阶段的改动。

## 子任务分配

1. `phase1_ui_parity`：截图 2 的右上角入口、面板 header、tab、分割线、toggle、高亮、
   拖动区域和响应式行为。
2. `phase2_workspace_editor`：彩色文件树、编辑器标签、语法高亮和文件浏览测试。
3. `phase3_terminal`：底部终端 dock、展开/收起、拖动高度和安全执行联动。
4. `phase4_contracts`：artifact/run 权威关系、trace title/ID，以及 0.4 子智能体接口。
5. `phase5_backend_split`：Repository、Agent API、application service 和前端 transport
   隔离。
6. `phase6_release_gate`：Playwright required CI、测试 Host、迁移 clone、备份恢复和版本
   一致性检查。

主代理负责整合、冲突处理、跨阶段测试、将候选分支 rebase 到最新 `origin/main`、
创建或更新 PR，以及最终发布前报告。PR 完成后必须停在 merge 之前；只有用户完成人工
测试并明确确认后，才继续合并、创建 tag 或发布。

## 发布前人工确认清单

- 右上角按钮和截图 2 的排列、间距、状态看起来一致；
- 文件树颜色、编辑器和语法高亮适合日常使用；
- 终端在页面底部，展开和拖动不会破坏聊天区域；
- 0.3 不显示或启用 Subagents；
- 本地和远程项目均可浏览文件、查看产物、打开 DAG 和运行终端；
- 历史会话、附件、产物、运行记录和凭据都可读取；
- 用户完成人工测试并明确同意发布后，才执行 tag 和生产升级。
