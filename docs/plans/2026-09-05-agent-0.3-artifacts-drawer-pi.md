# Agent 0.3 Artifact、Drawer 和 Harness 替换实验计划

## 目标

继续在 PR #265 上完成用户可见的 Agent Workspace 稳定化，并验证前端是否真正
依赖 Harness 无关的呈现协议。生产环境继续使用 `0.2.0`；本计划完成前不创建
`0.3.0` tag、不发布镜像，也不替换生产实例。

## 已确认的产品规则

- 只有 Agent 调用 `publish_artifact` 才能创建 Artifact。
- Artifact 表示明确交付给用户的文件；代码修改、中间文件、测试输出和任何命令
  输出都不属于 Artifact。
- 同一个逻辑交付物使用稳定 Artifact ID，每次重新发布生成只读版本；默认显示最新
  版本。
- 短命令输出显示在对话中的工具卡片里。过长输出保存为 Agent 执行记录，用户可按
  需打开完整内容，但它不出现在 Artifacts 列表。
- 右侧 Drawer 使用 `+` 添加工具或资源 Tab。Tab 可以关闭、排序，按 Session 记住
  顺序和选中状态；Drawer 宽度按浏览器记住。
- 最右侧按钮只负责显示和隐藏 Drawer；Terminal 继续位于底部 Dock。
- Jump to latest 立即滚到底部，并恢复自动跟随新内容。
- HTML 预览运行在独立 origin、没有 BioinfoFlow Cookie、不能访问文件系统且默认断网
  的隔离环境中。其他支持的格式按媒体类型预览，未知格式提供下载。
- pi 只做 Harness adapter 架构实验。它必须复用 BioinfoFlow 的 Session、Run、审批、
  Sandbox、Workspace 权限和 Artifact 存储，不把安全边界交给 pi。

## 领域模型

```text
Workspace File
  Agent 工作过程中创建或修改的普通项目文件，可继续变化

Artifact
  Agent 明确调用 publish_artifact 后产生的用户交付快照

Artifact Version
  一个 Artifact 的不可变内容版本，带 checksum 和发布来源

Tool Output
  一次工具调用的 stdout、stderr、退出码、工作目录、耗时和截断信息

Agent Execution Record
  一次 Agent Run 的模型调用、工具调用、审批、取消、错误和工具输出索引

Terminal
  用户主动打开的交互式底部 Dock，不等于 Tool Output
```

## 分批实施

### Batch 0：计划和领域词汇

交付：本计划、领域词汇更新、PR 分批策略。

验收：Artifact、Tool Output、Agent Execution Record、Terminal 的含义在代码、测试
名称和 UI 文案中不再互相替代。

### Batch 1：Artifact 和 Tool Output 分离

测试先覆盖公开行为：

1. Agent 没有调用 `publish_artifact` 时，写入的 HTML 只出现在 Workspace Files。
2. Agent 调用 `publish_artifact` 后，Artifact 列表出现文件，并带 session、run、媒体
   类型、checksum 和可下载内容。
3. Bash 输出过长时，完整输出可以查询，但 Artifact 列表为空，不出现命令标题。
4. 同一个声明重复提交时返回同一个 Artifact ID；内容变化时产生新版本，旧版本仍可读。
5. 前端只接收后端确认的 Artifact DTO，不根据工具名、文件时间或聊天文本猜归属。

实现要点：

- 把命令输出从 `agent_artifacts` 的用户交付查询中移出，使用明确的 Tool Output/执行
  记录类型和查询接口。
- `publish_artifact` 复制不可变快照，前端按 MIME 注册预览器：HTML、图片、PDF、CSV/TSV、
  XLS/XLSX、JSON、YAML、XML、Markdown 和常见代码；其他格式显示下载。
- HTML 预览保持隔离，不继承应用 Cookie，不允许访问本地文件系统，网络默认关闭。
- Repository 只负责数据库读写；Artifact service 通过 Repository 方法操作数据。

提交：`feat: separate agent artifacts from tool output`

### Batch 2：右侧多 Tab Drawer

测试先覆盖 DOM 和键盘行为：

1. `+` 打开工具菜单，选择 Files、Artifacts、DAG 或 Browser 后创建一个 Tab。
2. 多个 Tab 可以同时存在，点击 Tab 切换内容，关闭 Tab 不影响其他 Tab。
3. Tab 顺序、当前选中 Tab 和关闭后的焦点恢复按 Session 刷新后保持。
4. 最右侧按钮只切换 Drawer 显示状态，不创建或删除 Tab。
5. 文件和 Artifact 可以作为独立资源 Tab 打开；同一资源重复打开时聚焦已有 Tab。
6. 桌面、平板和手机的 Drawer 均能打开、关闭、切换和恢复状态。

实现要点：

- 用一个前端 `TabState` 管理 tab id、kind、resource key、顺序、选中项和关闭行为；
  后端只提供内容 DTO。
- `+` 菜单和 Tab strip 属于 Drawer 导航，不把固定工具按钮永久铺在右上角。
- 关闭当前 Tab 时选择最近使用或相邻 Tab，并把焦点放回可见 Tab。
- 最后一个 Tab 关闭后 Drawer 显示空状态；再次添加 Tab 时重新打开 Drawer。

提交：`feat: add session-scoped workspace drawer tabs`

### Batch 3：Jump to latest 和 Terminal 视觉

测试先覆盖用户行为：

1. 用户向上阅读时，新消息不会改变当前阅读位置，只显示 Jump to latest。
2. 点击 Jump to latest 后立即到达底部，按钮消失，后续消息继续自动跟随。
3. Terminal Dock 只保留最顶端边界，Header 和内容共用背景，Tab 用轻阴影区分。
4. Terminal Dock 与右侧 Drawer 同时打开时，二者不互相改变尺寸或焦点。
5. 1440、1024、390 三种宽度均通过截图和交互测试。

实现要点：

- Jump to latest 使用同步到底逻辑，忽略平滑滚动期间产生的中间 scroll 事件。
- Terminal 不把交互式会话混入 Agent Tool Output；底部 Dock 仍使用现有安全执行和
  环境路由。
- 如果保留 Terminal 的 `+`，只有在多终端会话有明确数据模型和测试后才启用，不能
  留下不可用的空按钮。

提交：`fix: restore agent transcript following and terminal hierarchy`

### Batch 4：pi Harness adapter 实验

先建立契约测试，再接入 pi：

1. 同一个 Session/Run 通过当前 Harness 和 pi adapter 都能生成相同的 Presentation
   Contract。
2. Tool Call、Tool Action、Approval、Cancel、Retry、Artifact、Tool Output 和重连
   的公开行为一致。
3. pi 的原始事件不会穿过后端进入前端；前端只看到 BioinfoFlow DTO。
4. Sandbox、Workspace 权限、凭据、审计和 Artifact 发布仍由 BioinfoFlow 管理。
5. pi 不提供 `publish_artifact` 时，BioinfoFlow host adapter 必须补充该能力；没有
   明确发布动作时，任何文件都不能出现在 Artifact 列表。

实现要点：

- 先把 `AgentRuntime` 的工厂类型从具体 `AgentHarness` 收窄为 Harness Protocol。
- 用 Python adapter 驱动 pi 的 RPC/SDK sidecar；pi 事件只在 adapter 内转换。
- 把模型、工具、审批、取消、事件流和恢复能力分别写成小接口，不建立第二套会话
  存储或权限系统。

提交：`feat: add pi harness adapter contract`

### Batch 5：CI、审查和发布前门禁

- Playwright 触发规则覆盖 `app-layout.tsx`、Navbar、面板 controller、媒体断点、
  Workspace/Terminal 组件和对应测试。
- CI 必须把三种 viewport 的浏览器结果作为 required gate；路径未命中时不能静默
  跳过相关保护。
- 每个 batch 单独运行对应后端/前端测试、Lint、Build 或 Playwright，并由独立 review
  检查公开 seam、领域边界和测试质量。
- 完成真实 `0.2.0` 数据副本的升级、备份、恢复和旧版读取演练后，才讨论发布。

## 暂不做的事

- 不在 0.3 恢复 Subagents。
- 不把 Claude Code 的 claude.ai 托管 URL、分享权限或 MCP connector 直接搬进本地产品。
- 不把 pi 当作权限、Sandbox、凭据或 Artifact 存储的事实来源。
- 不在本计划中统一版本号、创建 tag 或替换生产环境。
